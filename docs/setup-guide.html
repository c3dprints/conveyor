Pi Poop Conveyor

Setup guide, version 1.0.3: Raspberry Pi controller for a Bambu Lab purge ("poop") conveyor

This project runs a waste-filament conveyor belt from a Raspberry Pi 4. The Pi listens to your Bambu Lab printers over their local network connection (MQTT), and switches the belt motor on when a printer needs it. You can also run it by hand from a 5-inch touchscreen or from any phone or PC on your network. It replaces the ESP32 + MOSFET board from the original MakerWorld design (model 2594649): the motor plugs straight into the Pi's USB port.

2. Install Raspberry Pi OS

  1. On your PC, install Raspberry Pi Imager from raspberrypi.com/software.
  2. Choose device Raspberry Pi 4, OS Raspberry Pi OS (64-bit) (the desktop version), and your microSD card.
  3. When asked to apply OS customisation, choose Edit settings and set:
    • Hostname: conveyor. This makes the page reachable at http://conveyor.local.
    • Username and password: your choice (this guide uses admin).
    • Wi-Fi name and password, and your country and time zone.
    • On the Services tab, turn on SSH with password login.
  4. Write the card, put it in the Pi, and power it on. The first boot takes a few minutes.
Tip: give the Pi a fixed IP address in your router (often called a DHCP reservation or Fixed IP). Then its address never changes.

3. Connect the touchscreen

4.3" DSI screen (ribbon cable)

With the Pi powered off, connect the ribbon cable to the Pi's DISPLAY connector (contacts facing the HDMI ports on a Pi 4) and the screen's power wires if it has them. Power on. The Pi finds the screen by itself, so skip the rest of this section. After installing the software (section 5), open Screen settings and pick 4.3" DSI screen if it isn't already selected. That turns off the HDMI output, clears the HDMI boot setting below, and keeps the controls on the 4.3" screen.

5" HDMI screen (Elecrow RC050)

  1. With the Pi powered off, press the screen onto the GPIO header so it sits on pins 1–26 (the end nearest the SD card), and connect the HDMI cable to the Pi's HDMI 0 port (the one beside the USB-C power port).
  2. Power on. Open a terminal on the Pi (or connect with ssh admin@conveyor.local).
  3. Turn on the touch controller. Open the boot config: 
    sudo nano /boot/firmware/config.txt
    Add these two lines at the very end, under [all], then save (Ctrl+O, Enter, Ctrl+X): 
    dtparam=spi=on
dtoverlay=ads7846,cs=1,penirq=25,penirq_pull=2,speed=50000,keep_vref_on=0,swapxy=0,pmax=255,xohms=150,xmin=200,xmax=3900,ymin=200,ymax=3900
  4. Set the screen's resolution. Open: 
    sudo nano /boot/firmware/cmdline.txt
    This file is one single line. Go to the end of it, add a space, then add the following, without starting a new line: 
    video=HDMI-A-1:800x480M@60D
  5. Reboot: sudo reboot

Portrait mode

Create the display layout file (this replaces any layout saved with the Screen Configuration tool):

mkdir -p ~/.config/kanshi
nano ~/.config/kanshi/config

Put this in it:

profile {
    output HDMI-A-1 enable scale 1.000000 mode --custom 800x480@60 position 0,0 transform 270
}

transform 270 is portrait. Use 90 for portrait the other way up, or normal for landscape. After the software is installed you can also turn the screen with the Rotate 90° button, which saves the setting for you.

Make touch follow the screen

nano ~/.config/labwc/rc.xml

Just before the last line (</openbox_config>) add:

<touch deviceName="ADS7846 Touchscreen" mapToOutput="HDMI-A-1" mouseEmulation="yes"/>

If the file doesn't exist yet, copy the system one first: cp /etc/xdg/labwc/rc.xml ~/.config/labwc/. Reboot and check that a tap lands where your finger is.

4. Connect the motor

  1. Mount the gear motor in the printed conveyor as the MakerWorld model shows.
  2. Plug the motor's USB plug into any USB port on the Pi.

That's all the wiring. The software switches the USB ports' power on and off with uhubctl, so the motor spins only when it should.

All four USB ports switch together. The Pi 4 can't power its USB ports one at a time, so whenever the belt is off, every USB port is off. Don't use the Pi's USB ports for a keyboard, mouse or USB drive you need. Use the touchscreen, SSH or VNC instead. A second USB motor can share the ports, but both will always run together. USB power is on/off only, so the Motor speed setting has no effect on a USB motor.
Turning the ports on takes about 3–4 seconds, so expect a short pause between pressing Run and the belt moving.

5. Install the conveyor software

  1. Copy the project folder to the Pi's home folder as ~/poop-conveyor-pi. Either clone it from GitHub: 
    git clone https://github.com/c3dprints/conveyor.git ~/poop-conveyor-pi
    or copy it from your PC (in a PC terminal, from the folder that contains it): 
    scp -r poop-conveyor-pi admin@conveyor.local:~/
  2. On the Pi, run the installer: 
    cd ~/poop-conveyor-pi
sudo bash install.sh
  3. Reboot: sudo reboot

The installer:

  • installs the needed packages: Flask, paho-mqtt, gpiozero, uhubctl and avahi (for conveyor.local)
  • allows the app to switch USB power and restart itself without a password prompt (a small file in /etc/sudoers.d)
  • creates config.json from config.example.json (readable only by your user, since it will hold printer access codes)
  • sets the app up as a service called conveyor that starts at boot and restarts itself if it stops
  • opens the controls full screen on the touchscreen at login
  • adds a Conveyor Control icon to the desktop that reopens the controls (and restarts the service if needed)

Test the motor

sudo systemctl stop conveyor
python3 ~/poop-conveyor-pi/conveyor.py --test
sudo systemctl start conveyor

The belt should run for 3 seconds and stop.

6. Get your printers ready

For each Bambu Lab printer you need three things. The setup page fills in the first two for you:

ItemWhere to find it
IP addressPrinter screen: Settings → Network (WLAN). Found automatically if the printer is on the same network as the Pi.
Serial numberPrinter screen under Settings (device information), or Bambu Studio's device page. Found automatically along with the IP.
Access codePrinter screen: Settings → Network (WLAN). An 8-character code.
The connection is local only: the Pi talks directly to each printer on port 8883 with the user name bblp and the access code. Nothing goes through Bambu's cloud. If the access code is right but the connection is rejected (common on newer X1 firmware), turn on LAN Only mode and Developer Mode in the printer's network settings.

Printers show up automatically only on the Pi's own network. For printers on a different network (for example 192.168.2.x while the Pi is on 192.168.1.x), use the Scan box on the setup page (next section).

7. Add printers to the conveyor

  1. On a PC or phone on the same network, open http://conveyor.local/setup (or http://<Pi IP address>/setup).
  2. Printers found on the network are listed at the top. If one on another network is missing, type that network (e.g. 192.168.2.0/24) in the Scan box and press Scan. That network is rechecked every 15 minutes from then on.
  3. Press Add next to each printer, then:
    • give it a name you'll recognise,
    • type its access code,
    • pick which conveyor it uses (Pi USB belt),
    • press Test connection and wait for the green result.
  4. Press Save. The printers connect within a few seconds and appear on the touchscreen.

Access codes stay on the Pi. They're never sent back to the browser; leave the field blank later to keep the saved code. If a printer's IP changes, it reappears in the found list with an Update IP button.

8. Using the controls

The touchscreen and http://conveyor.local show the same controls.

Belt

  • Run 30s: runs the belt for 30 seconds.
  • On: runs the belt continuously (stops by itself after 1 hour).
  • Off: stops it now.

Automatic mode

While Automatic mode is on, the belt runs when any assigned printer needs it:

WhenSettingDefault
Every few minutes while printingRun every (min) / Run for (s)every 5 min, for 60 s
Shortly after a filament change (AMS purge)After filament change (s)10 s
When a print finishes or failsAfter print ends (s)15 s

Change the times with the + and − buttons under Settings. Changes are saved straight away. Several printers can share one belt; their runs simply overlap.

Buttons at the bottom of the page

  • Screen settings: pick the screen (5" HDMI or 4.3" DSI), the resolution (5" HDMI only), the zoom and the rotation. After switching screens or resolution you have 20 seconds to press Keep; otherwise it switches back by itself, so a wrong choice can't leave the screen blank. The same page works from a phone or PC at http://conveyor.local/screen.
  • Printer setup: opens the setup page from section 7 on the Pi's screen.
  • Shut down Pi: asks Shut down the Pi? first. After Yes, shut down, wait until the Pi's green light stops flashing (about 20 seconds) before unplugging it. To start it again, unplug the power and plug it back in.
  • Screen off: turns the screen black. The screen also goes black by itself after 5 minutes without a touch. Tap anywhere to wake it; the first tap only wakes the screen and doesn't press anything. (This panel shows white if the Pi stops sending a picture, so the screen is blacked out rather than switched off. The backlight stays on.)
  • Rotate 90°: turns the screen a quarter turn clockwise each press and remembers the position.
  • Exit to desktop: closes the full-screen controls. Tap the Conveyor Control desktop icon to bring them back.

On the touchscreen, drag up or down on an empty area (not on a button) to scroll.

The bottom of the page shows the addresses to use from other devices and the app version.

9. Network access

  • http://conveyor.local works even if the Pi's IP address changes. It works on Windows 10/11, macOS, iPhone and most recent Android phones.
  • If your PC or phone is on a different network or VLAN than the Pi, .local names won't reach it unless your router repeats them (UniFi: Settings → Networks → Multicast DNS). The IP address always works.
  • From outside your home: install Tailscale (free) on the Pi and on your phone or PC. Don't forward a port on your router: the page has no login, so anyone who found it could run the belt and change printer settings.

10. Troubleshooting

ProblemWhat to do
Controls not showing on the touchscreenTap the Conveyor Control desktop icon. It restarts the service if it isn't answering.
Want to see what it's doingjournalctl -u conveyor -f shows the live log (printer connections, belt on/off, errors).
Restart the appsudo systemctl restart conveyor
Belt doesn't stopCheck the log for uhubctl ... failed. While idle, the app sends "off" again every 30 seconds. Check the ports with sudo uhubctl -l 1-1 and sudo uhubctl -l 2: all should read off.
Belt never startsRun the motor test in section 5. Make sure the printer has a conveyor picked on the setup page and Automatic mode is on.
"Access code rejected"Re-check the code on the printer screen (it changes if you reset it). Then turn on LAN Only + Developer Mode.
Printer not foundScan its network on the setup page, or type its IP and serial in by hand.
Touch is off or mirroredCheck the <touch> line in ~/.config/labwc/rc.xml, then reboot.
Screen blank or wrong sizeCheck the video= entry is on the single line in cmdline.txt and appears only once.
Screen whiteThe Pi isn't sending a picture. Check the HDMI cable and that the Pi has finished booting.

11. Updating

The Pi checks GitHub for a new release every 6 hours. When one is out, the control page shows Update available with an Install button, and the setup page's Software card has Check for updates and Install update. Installing downloads the release, checks it, and restarts the app; the belt stops for a few seconds and the screen reloads itself. If the new version is broken it is not installed and the old one keeps running. Tick Install updates automatically to have the Pi do this by itself whenever no belt is running.

Your printers and settings live in config.json, which updates never touch. Run sudo bash install.sh again only if the release notes say so.

Publishing an update (for the maintainer)

git commit -am "what changed"
git tag v1.0.3        # matches __version__ in conveyor.py
git push origin main --tags

The Pi only installs tagged releases, so work pushed to main without a tag isn't sent out.
